# ELEC3117 2S BMS 控制程序使用说明

## 1. 这版代码包含什么

主程序是 `ELEC3117_BMS_Controller.ino`。它在你已经验证过的 ESP32 测试代码上加入了：

- MCP3424 四通道非阻塞轮询：CH1/CH2 测两节电池，CH3/CH4 测两只 NTC；
- INA219 输入电压、总输入电流和总输入功率测量；
- 网页注明 BQ2057 约 0.60 A 是硬件充电限制，软件不会错误地用 INA 总输入电流闭环控制它；
- 电芯电压 SOC 粗略估算，电池包 SOC 取两节中较低值；
- Solar EN 固定参考电压准 MPPT、输入塌陷检测和两种重新试探模式；
- 双 NTC 整包温控：最低温度决定是否需要加热，最高温度决定降功率或停止；
- R26、R32 加热与被动均衡复用；
- 加热中联合均衡、独立均衡，以及 50 mV 启动、20 mV 停止滞环；
- 所有输出统一安全仲裁；
- 可定位的故障码、故障位置、测量证据、严重等级和自动处理；
- 串口菜单、手机网页、NVS 参数保存和最近约 10 分钟 CSV 数据下载。

程序每次重启后都会关闭所有功率输出，而且自动控制默认保持关闭。检查测量结果正确后，必须由你手动启用自动控制。

## 2. 当前硬件映射

| 功能 | ESP32 GPIO / 通道 |
|---|---|
| MCP3424 SDA / SCL | GPIO32 / GPIO33 |
| INA219 SDA / SCL | GPIO16 / GPIO17 |
| Solar EN | GPIO25 |
| Load EN | GPIO26 |
| Heater1，R26 | GPIO27 |
| Heater2，R32 | GPIO13 |
| LED | GPIO18 |
| Battery 1 | MCP3424 CH1 × 4.00 |
| Battery 2 | MCP3424 CH2 × 4.00 |
| NTC1，Battery 1 | MCP3424 CH3 |
| NTC2，Battery 2 | MCP3424 CH4 |

代码假定 Solar、Load 和两路 Heater 的使能信号均为高电平有效。如果你的实测结果相反，把程序顶部相应的 `*_ACTIVE_HIGH` 改成 `false`。

## 3. 烧录前必须核对的参数

打开程序最前面的硬件配置区域，优先检查以下值：

1. `CELL1_DIVIDER` 和 `CELL2_DIVIDER`
   - 75 kΩ / 25 kΩ 分压使用 `4.00`；
   - 如果高侧已经换为 82 kΩ，使用约 `4.28`；
   - 最终应拿万用表读数与网页 B1/B2 对比，再用 `CELL1_CAL`、`CELL2_CAL`做小范围校准。

2. `NTC_SUPPLY_V`
   - 用万用表测量实际 3V3MCU；
   - 例如实测 3.27 V，就把 `3.300f` 改成 `3.270f`。

3. `INA_SHUNT_OHM`
   - 当前按原理图中的 0.05 Ω 设置；
   - 若实际采样电阻不同，必须修改。

4. `INA_CURRENT_SIGN`
   - 正常输入供电时若电流显示为负数，把 `1.0f` 改成 `-1.0f`。

5. 输出有效电平
   - 首次测试应断开 Heater 和 Load 功率路径，只用万用表确认 GPIO/栅极的开关方向；
   - 不要根据程序中的 HIGH/LOW 猜测 MOSFET 是否导通。

## 4. Arduino IDE 烧录

1. 安装 Arduino IDE 和 Espressif 的 ESP32 board package。
2. 新建同名文件夹 `ELEC3117_BMS_Controller`。
3. 把 `ELEC3117_BMS_Controller.ino` 放入该文件夹并打开。
4. 选择与你此前成功烧录相同的 ESP32 板型、串口和上传速度。
5. 编译并上传。
6. 打开 Serial Monitor，波特率设为 `115200`。

本程序只使用 ESP32 board package 自带的 `Wire`、`WiFi`、`WebServer` 和 `Preferences`，不需要另外安装第三方 Arduino 库。

## 5. 第一次上电建议顺序

### 阶段 A：只验证测量

1. 保持 Load、Solar EN 和两路 Heater 功率输出不能驱动危险负载。
2. 上电后确认串口出现：`All power outputs are OFF`。
3. 输入 `r`，检查：
   - B1、B2 与万用表差异是否合理；
   - NTC1、NTC2 是否接近室温；
   - INA 输入电压和电流方向是否正确；
   - 故障列表中是否有 ADC、NTC 或 I²C 故障。
4. 如果无电池上电，出现 `CELL1_ADC_FAULT`、`CELL2_ADC_FAULT` 属于预期；它们是关键故障并会锁存。接好电池、读数恢复后输入 `c` 清除。

### 阶段 B：验证 NTC 故障定位

NTC 接法为 `3V3 → NTC → ADC节点 → 3.3kΩ → GND`：

- 上方 NTC 开路时，节点趋近 0 V，程序报告 `NTC1_OPEN` 或 `NTC2_OPEN`；
- NTC 短路时，节点升高并接近 MCP3424 的 2.048 V 满量程，程序报告 `NTC1_SHORT` 或 `NTC2_SHORT`；
- 电压不是明显开路/短路，但换算温度超出 −30～80°C，报告 `NTC*_OUT_OF_RANGE`；
- 任意一只 NTC 失效，两路 Heater 和均衡都会被禁止，因为程序无法可靠判断整包最高温度。

### 阶段 C：分别测试 Heater

1. 电芯均应高于 3.45 V，两只 NTC 必须有效，最高温度必须低于 45°C。
2. 输入 `1`：Heater1/R26 以 50% 时间比例运行最多 10 秒。
3. 输入 `2`：Heater2/R32 以 50% 时间比例运行最多 10 秒。
4. 输入 `b`：两路同时测试最多 10 秒。
5. 随时输入 `0` 会进入安全模式并撤销所有请求。

网页或串口的 Heater 测试命令不是直接写 GPIO；欠压、过温、NTC 故障、运行超时和安全模式仍然可以阻止它。

### 阶段 D：测试 Solar 和 Load

1. 输入 `s` 请求一次受保护的 Solar 试探。
2. 程序打开 EN 前要求 INA 和两节电芯测量有效，并且两节均未过压。
3. 开启后约 500 ms 判断输入是否保持在 `Vref − 0.5 V` 以上、开关前后压降是否不超过约 1 V。
4. 连续三次运行采样过低会报告 `INPUT_COLLAPSE`，关闭 Solar EN，并等待恢复后再试探。
5. 输入 `l` 只切换 Load 请求；若有欠压或其他相应故障，最终 Load 输出仍保持关闭。

## 6. 手机网页

1. 手机连接 Wi‑Fi：
   - SSID：`ELEC3117-BMS`
   - 密码：`elec3117`
2. 浏览器打开 `http://192.168.4.1`。
3. 网页可查看两节电压、两只 NTC、SOC、INA、控制状态、占空比和故障表。
4. 网页按钮与串口命令使用同一个安全仲裁器。
5. `Download CSV` 下载 RAM 中最近 120 行数据；记录周期 5 秒，所以约覆盖最近 10 分钟。重启后记录清空。

网页可以保存以下参数：

| 参数 | 默认值 | 可调范围 |
|---|---:|---:|
| 加热启动温度 | 5°C | −10～15°C |
| 加热停止温度 | 10°C | 至少比启动高 2°C，最高 25°C |
| MPPT Vref | 10.0 V | 6～14 V |
| 均衡启动压差 | 0.050 V | 0.030～0.150 V |
| 均衡停止压差 | 0.020 V | 0.010 V 至启动值−0.010 V |
| 固定试探周期 | 10 s | 2～60 s |

45°C Heater 硬停止、60°C 严重过温、电芯严重欠压/过压、传感器有效性和 30 秒运行上限不能从网页修改。

| `r` | 实时状态和当前故障 |
| `f` | 只显示详细故障 |

| `q` | 关闭自动控制 |
| `s` | 请求受保护的 Solar 试探 |
| `l` | 切换 Load 请求 |
| `1` | Heater1/R26，10 秒 50% 测试 |
| `2` | Heater2/R32，10 秒 50% 测试 |
| `b` | 两路 Heater，10 秒 50% 测试 |
| `0` | 进入安全模式，撤销请求并关闭全部输出 |
| `x` | 离开安全模式；自动控制仍保持关闭 |

| `w` | 开关 Wi‑Fi 热点 |
| `m` | 显示菜单 |

## 8. 自动温控和均衡逻辑

- `tempMin = min(NTC1, NTC2)`：低于启动温度时提出整包加热请求；只有两节都达到停止温度才取消。
- `tempMax = max(NTC1, NTC2)`：达到 15°C 时限制功率，达到 45°C 时关闭两路 Heater 和 Solar，达到 60°C 时进入关键故障。
- 两只 NTC 温差持续超过 8°C：警告并把加热占空比减半。
- 温差持续超过 15°C 达 10 秒：关闭两路 Heater 和均衡。
- 无稳定输入时，只有 SOC 至少 40%、两节均至少 3.50 V 才允许自动加热；下降到 SOC 35% 或任一节 3.45 V 时停止。
- 正常加热时两路共同加热整个电池包。较高电芯对应的电阻占空比较高，较低电芯对应电阻占空比较低。
- 独立均衡要求两节均至少 3.80 V；压差达到启动值时对较高电芯放电，降至停止值时结束。
- 任何 Heater/均衡运行一轮最多 30 秒，然后强制冷却 10 秒。

## 9. 如何读故障表

每个故障包含：

- `Code`：具体故障码；
- `Severity`：Warning、Recoverable 或 Critical；
- `Location`：怀疑位置或确认的测量链路；
- `Measured / threshold`：判断依据；
- `Action`：程序已经自动关闭的功能；
- `latched`：即使读数恢复，也要在确认安全后输入 `c`。

例如 B2 持续低于 3.00 V 时会显示 `CELL2_UNDERVOLTAGE`，位置为 `Battery 2 / MCP3424 CH2`，并关闭 Load、两路 Heater 和均衡，但允许 Solar/BQ 充电路径尝试恢复电池。

Heater 没有独立电流传感器，因此故障结论只能是“疑似”：

- 单独运行 Heater1 但温升不足，程序可定位到 `Heater1 / R26 / GPIO27 path`；
- 单独运行 Heater2 时可定位到 R32/GPIO13；
- 两路同时运行却无温升，只能定位到两路加热路径或共同的导热接触；
- 命令关闭 20 秒后整包平均温度仍上升 3°C 以上，报告疑似 Heater 无法关闭。此时应立即人工断开电池并检查 MOSFET，而不是依赖软件关断。

## 10. 这版程序不能做到的事情

- INA219 位于输入端，所以 `INA current` 不是精确充电电流；Heater、ESP32、Wi‑Fi 和其他负载都会包含在内。
- BQ2057 STAT 没有接入 ESP32，因此程序不能确定显示“正在充电”或“充满”，只能观察输入和电压趋势。
- SOC 基于慢速电压查表，不是库仑计；充电、加热、Wi‑Fi 脉冲或大负载工作时可信度较低。
- 没有 Heater 支路电流传感器，无法仅凭软件绝对确认电阻开路或 MOSFET 损坏。
- EN 开关式准 MPPT 不是连续占空比 MPPT；它只能在输入塌陷时关闭并重新试探。
- 软件保护不能替代 MM3220、保险丝、充电器限制、电芯额定参数和人工测试安全措施。

演示前应先完成万用表校准、NTC 开短路测试、两路 Heater 单独测试、Solar 塌陷测试以及所有关键故障的输出关断验证。
